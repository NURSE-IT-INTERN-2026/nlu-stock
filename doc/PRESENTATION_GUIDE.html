Slide 9
USER ROLES & NLU ID
หนังสือและวัสดุ — บทบาทผู้ใช้ & โครงสร้าง NLU ID
3 Roles + 8 Categories + ID Format
  • ADMIN — สร้าง แก้ไข ลบข้อมูลได้ทุกส่วน รวมถึงจัดการ Users
  • STAFF — เพิ่ม แก้ไข ลบข้อมูลสินค้า เบิก-รับ-ปรับสต็อกได้ แต่จัดการ Users ไม่ได้
  • INSTRUCTOR — ดูข้อมูลและรายงานได้อย่างเดียว (View Only)
  • โครงสร้าง NLU ID: NLU-PREFIX-CODE-SUBCODE-SET-COPY
  • PREFIX 8 หมวด: KRU ELE BOOK TOY DUR CON MED KIT
  • เช่น NLU-KRU-001-A-1/1 = ครุภัณฑ์ รายการ 001 sub-code A set 1 copy 1
จากนั้นดู Core System — สถาปัตยกรรมทั้ง 3 ส่วน
Slide 10
ARCHITECTURE OVERVIEW
สถาปัตยกรรมระบบ
Frontend → Backend → Database
  • สถาปัตยกรรม 3 ชั้นแบบ fullstack ใน framework เดียว
  • Frontend: React 19 + Next.js 16 App Router — Server Components โดย default, Client Components เฉพาะที่ interactive
  • Backend: Route Handlers + Prisma ORM 7.8 — type-safe query, migration versioned
  • Database: PostgreSQL 16 รันใน Docker — port 5433, volume pgdata เก็บถาวร
  • ไม่ต้อง setup API server แยก — Next.js ทำได้ทั้งหมด
  • Auth: jose JWT + bcryptjs แทน next-auth
  • UI: shadcn/ui + Tailwind v4 — copy-paste components ไม่ lock-in

จากนั้นดู workflow การเบิกจ่าย
Slide 13
SYSTEM FLOW
เบิกจ่าย (DISPENSE)
ครบข้อมูล เร็วทันใจ สะดวกอำนวยในการใช้
  • Step 1 — ค้นหาหรือ QR Scanเพื่อหารายการสินค้า
  • Step 2 — เลือกรายการ + ใส่จำนวนที่ต้องการเบิก
  • Step 3 — เลือก Lot แบบ FIFO (First-In First-Out) ระบบแนะนำลำดับ แต่พนักงานเลือกเองได้
  • Step 4 — สร้าง Dispense Record พร้อมอัปเดต Available Qty, SubItem Status, Lot Qty ทั้งหมดใน transaction เดียว
  • ใช้ CartProvider context จัดการตะกร้า — เบิกได้หลายรายการพร้อมกัน
  • Prisma $transaction dispense แบบ atomic — ไม่เสี่ยงข้อมูลไม่ตรง
  • บันทึก UsageType: COURSE / ACTIVITY / OTHER

บันทึกการบำรุง (MAINTENANCE)
Preventive & Corrective Maintenance Tracking

SYSTEM FLOW
ปรับปรุงสต็อก (STOCK ADJUSTMENT)
จัดการเมื่อสินค้าเสีย หาย หรือนับไม่ตรง
  • ใช้เมื่อ พบสินค้าเสีย, หาย, นับไม่ตรง หรือจำหน่าย
  • ซ้าย: UI mockup — หน้ารายละเอียดสินคะ + ปุ่ม Adjust Stock
  • ฟอร์ม Adjust Stock: กรอก จำนวนที่นับได้ (Count on shelf), เลือก Reason, หมายเหตุ, แนบรูป Evidence
  • ขวา: Flowchart — พบเหตุการณ์ → เลือกปรับปรุง → ปรับปรุง → สร้าง StockAdjustment Record → อัปเดต Stock
  • AdjustmentReason: LOST DAMAGED_PENDING_REPAIR COUNT_MISMATCH DISPOSAL OTHER
  • ทุก adjustment สร้าง audit trail — เก็บ previousQty + newQty
